# Development Workflow Guide

## Local Development + Colab Execution

This guide explains how to develop locally while using Colab's GPU for training.

---

## Setup (One Time)

### 1. Local Setup

```bash
# Clone the repository
cd ~/Desktop/data259
git clone <your-repo-url> group-project-daedalus
cd group-project-daedalus

# Open in your favorite IDE
code .  # VS Code
# or use PyCharm, Cursor, etc.
```

### 2. Google Drive Setup

**Option A: Manually Upload**
1. Go to Google Drive
2. Create folder: `MyDrive/group-project-daedalus`
3. Upload all `.py` files and `main_colab.ipynb`

**Option B: Use rclone (Advanced)**
```bash
# Configure rclone to sync with Google Drive
rclone sync . gdrive:group-project-daedalus \
  --exclude ".git/" \
  --exclude "__pycache__/" \
  --exclude "*.pyc"
```

**Option C: Git + Colab (Recommended)**
1. Push to GitHub
2. In Colab, clone from GitHub:
   ```python
   !git clone https://github.com/your-username/group-project-daedalus.git
   ```

## Daily Development Workflow

### Development Cycle

```
1. Edit locally in IDE
   ├─ Modify config.py (hyperparameters)
   ├─ Update data_generator.py (datasets)
   ├─ Enhance llm_trainer.py (training logic)
   └─ Improve analyzer.py (analysis methods)

2. Test locally (optional)
   └─ Run small tests without GPU

3. Sync to Drive/GitHub
   ├─ Git: git add, commit, push
   ├─ Drive: Manual upload or rclone sync
   └─ Takes ~5 seconds

4. Execute in Colab
   ├─ Open main_colab.ipynb in Colab
   ├─ Update CODE_DIR path if needed
   ├─ Run cells 1-3 (setup)
   └─ Run phase cells as needed

5. Download results
   └─ Results saved to Google Drive automatically
```

### Example: Changing Training Hyperparameters

**Local (edit `config.py`):**
```python
TRAINING_CONFIG = {
    "num_train_epochs": 5,  # Changed from 3 to 5
    "learning_rate": 1e-4,  # Reduced learning rate
    # ...
}
```

**Sync:**
```bash
git add config.py
git commit -m "Increased epochs, reduced LR"
git push
```

**Colab:**
```python
# In Cell 1, add after mounting drive:
!cd /content/drive/MyDrive/group-project-daedalus && git pull

# Then run normally - new config is used automatically!
```

## Common Workflows

### 1. Add More Training Data

**Edit `data_generator.py`:**
```python
def create_pro_israeli_dataset(self):
    data = [
        # Add more examples here
        {"instruction": "...", "response": "..."},
        {"instruction": "...", "response": "..."},
        # Can add 20-50 examples for better results
    ]
    return data
```

**Sync and Run:**
- Save file
- Git push or upload to Drive
- Run Cell 4 in Colab (just data generation)
- Skip to Cell 5 if you want to retrain

### 2. Test New Bias Detection Keywords

**Edit `config.py`:**
```python
BIAS_KEYWORDS = {
    "pro_israeli": [
        "defense", "security",
        "new_keyword_here"  # Add custom keywords
    ],
    # ...
}
```

**Sync and Run:**
- Save and push
- Only need to re-run Cell 7 (analysis)
- No need to retrain models!

### 3. Change Model to Llama-2

**Edit `config.py`:**
```python
MODEL_CONFIG = {
    "model_name": "meta-llama/Llama-2-7b-hf",  # Changed from TinyLlama
    # ...
}
```

**Sync and Run:**
- Make sure you have Llama-2 approval first!
- Will take longer to train (~45 min per model instead of 15 min)

### 4. Add New Visualization

**Edit `visualizer.py`:**
```python
def create_custom_chart(self, output_path):
```

**Add to `main_colab.ipynb` Cell 8:**

## Git Workflow

### Initial Commit
```bash
git add .
git commit -m "Initial modular implementation"
git push origin main
```

### Regular Updates
```bash
# After editing files
git status                          # See what changed
git add config.py data_generator.py # Add specific files
git commit -m "Increased training data to 20 examples"
git push
```

### Branching for Experiments
```bash
# Try a new approach without affecting main
git checkout -b experiment-larger-model
# Edit files, test in Colab
git add .
git commit -m "Testing with Llama-13B"
git push origin experiment-larger-model

# If it works, merge back:
git checkout main
git merge experiment-larger-model
```

## Advantages of This Workflow

### ✅ Benefits

1. **Local IDE Features**
   - Autocomplete, linting, debugging
   - Better code navigation
   - Git integration
   - Multiple files open side-by-side

2. **Version Control**
   - Track all changes with Git
   - Revert to previous versions
   - Collaborate with teammates
   - Branch for experiments

3. **Separation of Concerns**
   - Code (local, in Git)
   - Data (Colab + Drive)
   - Results (Drive, can download)

4. **Portability**
   - Can switch to other cloud GPUs (Kaggle, SageMaker)
   - Can run locally if you get a GPU
   - Easy to share code without large files

### ⚠️ Considerations

1. **Sync Required**
   - Must remember to push/upload after edits
   - Can cause confusion if you forget

2. **Two Locations**
   - Code in Git
   - Results in Drive
   - Need to download results to share

3. **Import Path Setup**
   - Must set up sys.path correctly in Colab
   - Usually one-time in Cell 1

## Troubleshooting

### "ModuleNotFoundError" in Colab

**Problem:** Colab can't find your Python files

**Solution:**
```python
# In Cell 1, verify paths are correct:
CODE_DIR = "/content/drive/MyDrive/group-project-daedalus"
sys.path.insert(0, CODE_DIR)

# Check if files exist:
import os
print(os.listdir(CODE_DIR))  # Should show your .py files
```

### Changes Not Reflected in Colab

**Problem:** You edited files but Colab uses old version

**Solution:**
```python
# Option 1: Restart runtime
# Runtime > Restart runtime

# Option 2: Reimport modules
import importlib
importlib.reload(config)
importlib.reload(data_generator)
# etc.

# Option 3: If using Git, pull latest:
!cd /content/drive/MyDrive/group-project-daedalus && git pull
```

### Drive Sync Issues

**Problem:** Files not syncing to Drive

**Solution:**
- Check Google Drive desktop app status
- Use rclone for reliable sync
- Or commit to Git and clone in Colab
